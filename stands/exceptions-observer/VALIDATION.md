# Проверка поставки

Проверялось в Linux, без запуска Windows EXE и без Wine.

## Что подтверждено

- Полный `exception_probe.c`, включающий `asm_fragment.h`, собран и скомпонован настоящим llvm-mingw x64 с публичными Windows-заголовками и библиотеками.
- Компилятор: llvm-mingw `20260505-ucrt-ubuntu-22.04-x86_64`, clang 22.1.5, target `x86_64-w64-windows-gnu`.
- Флаги основного build: `-std=c11 -fms-extensions -O0 -g -Wall -Wextra -Werror -municode`.
- Дополнительный compile-only build с `-O2` также выполнен без предупреждений. Сценарий пользователя использует `-O0`.
- В собственном COFF-файле статически проверены все 18 точных инструкций, 18 таблиц unwind, сохранение nonvolatile GPR/XMM, границы восьми однобайтных PUSH, подготовка узора при пониженном RSP, полный post-RAX и общий snapshot для контролируемого выхода.
- В скомпилированном вызывающем C-коде присутствует настоящий обработчик `__C_specific_handler` для `__try/__except`; fault-инструкция находится в другой функции.
- Python-checker проверен 49 синтетическими unit-тестами в обычном Python и с `python -O`; также выполнен `py_compile`. Они проверяют формат, полноту и внутреннюю согласованность, не содержат утверждений о реальных Windows-значениях.

Команда повторения Python-тестов:

```text
python -m unittest -v test_checker.py
```

## Что не подтверждено

- Доставка и продолжение исключений на Windows 2022/2025: **не запускались**.
- PowerShell-сценарий: прошёл ручное чтение; PowerShell в среде проверки отсутствует, поэтому исполнение и проверка парсером **не выполнялись**.
- Эталонных `raw.jsonl` и `summary.json` в архиве нет. Они создаются только нативным пользовательским прогоном.
- Поведение другой реализации/переводчика не проверялось. Исходники и тесты Wine не создавались.

Скомпилированные EXE, объектные файлы, дампы и синтетические raw-файлы исключены из архива. Отчёт checker с полным учётом unsupported не заменяет полностью измеренную матрицу; см. README.
